### ① 신호 위반 오판정

위반 판정이 이동 **전** 신호 상태와 이동 **후** 거리를 비교했다. SUMO는 스텝 시작에 신호를 먼저 바꾸므로, 초록불로 바뀐 스텝에 정상 출발한 차가 적색 통과로 잡혔다. 이제 스텝 후 신호를 다시 읽어 여전히 적색일 때만 위반으로 센다(`_signal_still_red`). 원인은 건남님 보고서에서 찾은 것이다.

### ② 경로별 교통량 재배분

기존 배분은 출발지→목적지 조합마다 같은 양을 넣고, 샛길(우회전 전용 길) 수요를 2배로 했다. 그래서 차선 수와 무관하게 수요가 들어갔다.

- 신호 주기 125초 중 방향별 초록불은 20초다. 좌회전과 유턴이 한 차선을 같이 쓰는 곳은 느린 유턴(3 m/s) 때문에 처리량이 더 낮다.
- 6,000대/시간에서는 이런 차선(A1·A3의 4번, A5의 2번)에 처리 가능한 양의 2~3배가 들어갔고, 정식 평가 구간(800~1,450초) 밖까지 돌리면 도로 안 차량 수가 계속 늘었다.

새 배분은 시뮬레이션으로 찾았다(`scripts/tune_background_demand.py`). 배경차만 1시간(도착은 무작위, seed 5개) 흘려보내고, 대기가 신호 한 주기를 넘거나 끝까지 못 가는 경로만 8%씩 줄이기를 모든 경로가 통과할 때까지 반복한다.

| 종류 | 기존 (6,000 기준, 대/시간) | 새 배분 (4,740 기준) |
|---|---:|---:|
| 차선 3개 직진 (A1→A2, A2→A1) | 234 | 467~505 |
| 차선 2개 방향 (A3→A2, A3→A4, A4→A3, A5→A1) | 234 | 265~313 |
| 좌회전 (유턴과 차선 공유) | 234 | 84~99 |
| 유턴 | 75 | 39~49 |
| 샛길 | 303~607 | 234~276 |
| 샛길 비중 | 40% | 27% |

값은 `env/background_demand.py`의 `FLOW_SHARES`에 있다. `None`으로 두면 기존 계산식을 쓴다. 다른 도로처럼 경로 구성이 다르면 자동으로 기존 계산식을 쓴다.

### ③ A1·A3 맨 오른쪽 차선

A1과 A3 진입로에서 0번 차선은 샛길 갈림점까지 샛길 전용이었다. 교차로를 거쳐 우회전하는 차(A1→A3, A3→A5)는 갈림점 뒤 약 45m 안에서 1번→0번으로 옮겨야 했고, 1번 차선에 신호 대기 줄이 6대만 있어도 막혔다. ①② 이후 남은 차선 실패 15건이 전부 이 두 경로였다.

`inbound_lane_links`에서 0번 차선이 교차로의 0번 차선으로도 이어지게 했다. A2가 이미 같은 방식이다. A1·A3의 교차로 0번 차선은 샛길과 같은 도로로 가는 우회전 전용이라, 0번 차선은 계속 그 방향 우회전 전용이다. **도로 연결이 바뀌므로 이전 도로에서 만든 모델·데이터와 조건이 다르다.**

### ④ 교통 상태 복원 버그

③ 이후에도 특정 교통 상태(예: seed 0의 886초·888초)에서만 4개 운전 모델이 동시에 시간 초과됐다. 같은 교통량으로 배경차만 24시간 분량(seed 24개 × 1시간)을 돌리면 정체가 한 번도 생기지 않았다.

재현해 보니, `TrafficSchedule.restore`가 `moveTo`로 **교차로 내부 차선의 2단계**(좌회전·유턴이 교차로 안 대기 지점을 지난 뒤의 구간, 예 `:nC_30_0`)에 올려놓은 배경차가 첫 스텝부터 끝까지 움직이지 않았다. 교차하는 방향이 그 차를 기다리며 차례로 멈춰 교차로 전체가 막혔다.

이제 그런 차는 복원하지 않는다(영향받는 상태당 약 126대 중 1대). **이 복원 코드는 배경차 학습(`train_parallel.py --phase 2`)과 BC 평가도 함께 쓴다.** 지금까지 배경차가 있는 학습·평가의 일부 에피소드는 시작부터 교차로가 막혀 있었을 수 있다.

## 재현 방법

```bash
# 1) 평가 묶음 준비: 현재 도로 설정, 교통 seed 0~2
python scripts/evaluate_fixed_routes.py prepare analysis/traffic_4740_s0 \
    --reference results/eval_fixed_routes_20261119_214714/reference --current-road --traffic-seed 0

# 2) 운전 모델별 평가 (모델 하나에 약 12분, CPU 8코어)
python scripts/evaluate_fixed_routes.py evaluate analysis/traffic_4740_s0 IDM --expert car_idm --replicas 32
```

- `--current-road`: 저장된 reference의 도로 사본 대신 지금의 `env/road_config.py`로 도로를 만든다. 이 옵션이 없으면 ③ 이전 도로로 평가된다.
- `--traffic-seed`: 준비 운행으로 만드는 교통 상태와 평가 중 배경차 생성 순서를 바꾼다. 0이면 기존 벤치마크와 같다.
- 기본 교통량은 4,740이다(`--traffic-vph`로 변경).

배분을 다시 찾거나 점검할 때:

```bash
# 모든 경로가 건강한지 점검만 (약 1분)
python scripts/tune_background_demand.py analysis/traffic_4740_s0 - out.json 3600 5 check
# 드문 정체 찾기: seed 24개 × 1시간, 300초 넘게 선 차가 나오면 무엇이 막는지 출력
python scripts/find_background_gridlock.py analysis/traffic_4740_s0 - 3600 24
```
