# 차선별 배출량을 이용한 뷰어 유입 제어

`view_road.py`는 기본적으로 적응형 유입을 사용한다. Phase 2 학습에는 아직 적용하지 않는다.

```powershell
.\.venv\Scripts\python.exe -X utf8 view_road.py
# 같은 도로에서 고정 수요와 비교
.\.venv\Scripts\python.exe -X utf8 view_road.py --fixed-traffic
# GUI 없이 준비 운행 250초 + 1시간 검증
.\.venv\Scripts\python.exe -X utf8 view_road.py --nogui --seconds 3850
```

## 측정과 기본 유입량

- 측정 위치는 최종 출구가 아니라 각 신호 제어 차선의 정지선이다.
- 차량이 그 차선에서 실제 연결된 교차로 내부 차선/진출 도로로 이동했을 때 1대 배출로 센다.
  같은 도로 안 차선 변경, 사라진 차량, 순간이동 시작은 배출로 세지 않는다.
- 최근 5개의 유효 녹색 구간에서 배출된 대수의 평균을 사용한다.
  유효 구간은 처음부터 관측한 완전한 녹색 구간 중 저속 대기 차량이 2대 이상 관측된 구간이다.
  빈 녹색 구간은 제외하며, 대기 차량이 있는데 0대가 나간 구간은 포함한다.
- `차선 기준 유입량(대/시간) = 녹색 1회 평균 배출 대수 × 3600 / 신호 주기(초)`.
  현재 주기는 125초다. 황색 중 배출은 녹색 배출량에 더하지 않는다.
- 첫 측정 전에는 기존 경로 가중치로 나눈 수요를 사용하되, 초기 예산을
  `녹색 시간 / 가정한 출발 간격 2.5초 × 3600 / 신호 주기` 이내로 제한한다.
  동일 연속 차선을 공유하는 유턴/좌회전 측정 지점은 초기 예산을 나누어 쓴다.
  2.5초는 초기 설정용 가정이며 측정 용량이 아니다. 측정 후에는 관측 평균으로 대체한다.
  이는 관측 배출량이지 최대 포화 교통 용량의 추정값은 아니다.
- 공유 차선은 좌회전/유턴을 합쳐 측정하고, 유턴 지점과 중앙 정지선이 별개이면 각각 측정한다.
- 저속 대기열은 공유하지만, 평균 배출량 학습에 쓸 대기 차량은 해당 지점에서
  해당 방향으로 통과할 경로의 차량만 센다. 좌회전 차량의 대기로 유턴 배출량을
  0으로 잘못 학습하지 않도록 분리한다.

## 짧음 / 김 두 상태

10초마다 유입 요청 속도를 조절한다.

| 조건 | 동작 |
|---|---|
| 대기열 비율 30% 이하 | 짧음: 차선 기준 유입량의 110% |
| 대기열 비율 60% 이상 | 김: 차선 기준 유입량의 90% |
| 두 기준 사이 | 직전 짧음/김 판단 유지 |
| 대기열 비율 90% 이상 | 해당 차선에 배정하는 새 유입 요청 보류 |

### 미처리 차량의 재누적 방지

길이 판단과 별도로, 완전한 녹색이 끝날 때 해당 경로의 차량 중 아직 정지선 이전에
있는 차량을 센다. 정지한 차량뿐 아니라 움직이고 있어도 아직 통과하지 않은 차량을
포함한다. 이미 도로에 진입한 이 차량들도 다음 신호의 처리 물량이기 때문이다.

- 잔여 차량이 녹색 1회 평균 배출량보다 많거나, 2회 연속 녹색에서 잔여 차량이
  2대 이상이고 줄지 않으면 유입 억제를 시작한다.
- 억제 계수는 `max(0, 1 - 잔여 차량 / (2 × 녹색 1회 기준 배출량))`이다.
  기존 차량을 처리할 여유를 우선 확보하는 값이며, 2주기 안 해소를 보장하는 값은 아니다.
- 잔여 차량이 녹색 2회분 이상이면 새 유입을 보류한다.
- 같은 연속 차선을 공유하는 유턴/좌회전에는 가장 낮은 억제 계수를 함께 적용한다.
- 녹색 종료 시 잔여 차량이 1대 이하로 줄어든 것을 확인한 뒤 억제를 해제한다.
  단순히 녹색 중 정차 차량이 움직이기 시작했다고 해제하지 않는다.
- 긴 대기열도 녹색에 처리된다면 이 추가 억제는 작동하지 않는다.
  기존 길이 기준의 완만한 조절과 90% 포화 보호는 유지한다.

측정 전에는 공유 차선의 초기 예산을 기준 배출량으로 환산한다.
배출량 측정 이후에는 관측 평균을 사용한다. 제어 갱신 간격은 10초이며,
이미 도로에 들어온 차량을 삭제하지 않는다.

각 진입로 A1~A5의 차선을 입구에서 중앙 교차로 정지선까지 하나의 연속 차선으로 본다.
중간 분기·합류·유턴 지점의 내부 연결 차선도 포함한다. 차선 수가 바뀌는 곳은 실제 연결을
따라 추적하며, 상류 연결이 여러 개여도 모두 측정한다. 병렬 분기의 길이를 더하지 않고
가장 긴 연결 경로를 전체 길이로 사용한다. 동일 차량은 같은 측정 차선 안에서 한 번만 센다.

`대기열 길이 = 중앙 정지선에서 가장 먼 1m/s 이하 차량의 뒤끝까지 거리`.
중간에 20m 넘는 틈이 생겨도 상류의 저속 정체는 제외하지 않는다. 따라서 이 값은
차량이 연속으로 서 있는 길이보다 큰, 정체 꼬리까지의 거리일 수 있다.
`대기열 비율 = 대기열 길이 / 입구부터 중앙 정지선까지의 연속 차선 길이`.

A2 유턴 차선과 중앙 좌회전 차선은 `A2_in1_3 → :nM_A2_0_4 → A2_in_4`를 합친
254.11m를 공유한다. 배출량은 각 신호 지점에서 따로 측정하지만 유입을 줄일 때는
공유 차선의 혼잡을 함께 반영한다. 녹색 직후 틈으로 정체가 사라진 것으로 판단하지 않도록
현재 및 직전 신호 주기의 최대 대기열 비율을 제어에 사용한다.

```powershell
# 판단 기준 변경
.\.venv\Scripts\python.exe -X utf8 view_road.py --queue-short 0.25 --queue-long 0.65
```

## 차량 생성

- 전체 유입 요청 상한은 기본 5000대/시간이며 `--traffic-vph`로 변경한다.
- 차선별 예산을 그 차선으로 갈 수 있는 경로에 기존 수요 비중대로 나눈다.
  여러 차선을 쓸 수 있는 경로는 각 차선 예산에 비례해 배정한다.
- 출발 차선은 배정받은 신호 차선에 도달하기 위한 차선 변경 비용이 최소인 차선에서 선택한다.
  따라서 이전의 무작위 출발과 비교하면 출발 차선 배분도 달라진다.
- 신호를 거치지 않는 우회 경로는 녹색 배출 기준을 만들 수 없어 기존 비례 수요를 유지한다.
- 경로별 진입 대기 차량이 있거나 선택한 출발 차선 입구가 막혔으면 추가 생성을 보류한다.
  보류한 요청을 나중에 몰아서 생성하지 않는다.
- 배출된 차량 외에 도로 위 차량을 유입 제어 목적으로 삭제하지 않는다.
  SUMO의 충돌 제거, 기본 순간이동 복구 및 최대 출발 지연 125초는 그대로다.

## 확인할 파일

기본 출력 경로는 `analysis/view_road_adaptive/`다. `--metrics-dir`로 바꿀 수 있다.

- `lanes.csv`: 10초마다 차선별 대기열 비율, 짧음/김 상태, 녹색 평균 배출 대수,
  유효 녹색 누적 횟수, 기준 유입량, 차선 예산과 전체 유입 요청량.
  차선 예산은 전체 유입 상한을 적용하기 전 값이다.
- `queue_corridors.json`: 측정 차선별 중앙 정지선, 포함 구간, 내부 연결 차선,
  구간별 거리와 전체 길이. `lanes.csv`에도 대기열 길이(m), 전체 길이(m), 저속 차량 수,
  현재/직전 주기 최대 비율, 실제 제어에 사용한 혼잡 비율을 기록한다.
- `lanes.csv`의 `residual_after_green`은 녹색 종료 시 미통과 차량 수,
  `committed_before_stop`은 현재 미통과 차량 수다. `nonclearing_greens`, `draining`,
  `drain_factor`, `shared_drain_factor`로 유입 억제 이유와 공유 차선 적용을 확인한다.
- `network.csv`: 실제 누적 유입/배출, 도로 안/진입 대기 차량 수, 순간이동 횟수,
  전체 유입 요청량과 생성 보류 횟수.
- `summary.json`: 종료 시점 요약. 누적 수치는 빈 도로에서 시작한 시점부터다.

적응형 GUI는 자동 재생한다. GUI 창을 닫으면 기록을 정리하고 종료한다.
`--fixed-traffic` GUI는 기존처럼 재생 버튼을 누르는 방식이다.

## 현재 제어 검증과 정식 평가의 구분

뷰어의 적응형 유입 제어 검증(seed 0, 준비 운행 250초 후 3시간):

- 유입 11058대 / 배출 11049대, 도로 안 차량 108→117대.
- 종료 진입 대기 0대, 순간이동 0회.
- A2 시간별 평균 대기열 49.4 / 43.2 / 53.3m.
- A5 시간별 평균 대기열 51.4 / 56.0 / 58.7m.
- A5 시간별 최대 대기열 113.9 / 154.5 / 120.6m. 긴 대기열은 여전히 발생한다.
- 원자료: `analysis/archive/traffic_diagnostics/view_road_residual_pipeline_long/`.

이는 단일 난수 실행에서 누적 추이를 본 검증이며, 모든 수요 조건에서의 안정성이나
병목 해소를 보장하지 않는다. 출발 차선 배분도 함께 바뀌므로 변화 전체를 피드백만의
효과로 해석하지 않는다. 이전 단계의 원자료는 `analysis/archive/traffic_diagnostics/`에 보관했다.

사용자가 지정한 정식 완주율 평가는 `scripts/evaluate_fixed_routes.py`다.
현재 평가 결과 위치는 `analysis/fixed_routes_current_6000_20261120/`이며,
고정 수요/중앙 차선 출발 벤치마크다. 뷰어의 적응형 유입 제어는 실행하지 않는다.
별도로 수행했던 전체 차량 추적 100% 결과는 정식 평가와 다른 보조 지표다.
관련 코드와 검사는 `analysis/archive/background_cohort_evaluation/`에 보관했다.

구현 파일과 결과의 전체 구분은 `docs/traffic_work_changes.md`를 참고한다.
