전문가 데이터 수집 → 분할 및 선별 → BC 학습 → BC 평가

## 전문가 데이터 수집

- 도로 환경 설정
  - 배경차량 교통량: 윤재님의 traffic calibration 교통량 사용 (총 교통량 4740대/시간)
  - 배경차량 타입 비율: Krauss 35% / IDM 30% / EIDM 20% / ACC 15%
  - 배경차량 속도를 위한 추월 (lcSpeedGain) 설정: IDM만 1.0 (True) -> 속도를 위해 추월하는 것을 학습하기 위해
  - 신호 체계: 단순 신호 체계

- 전문가 데이터 수집
  - 전문가: IDM 단독
  - 목표 데이터: 24개 경로 데이터
  - 목표 수: 경로당 20,000회 (약 1억 쌍 예상)

### 전문가 데이터 수집 알고리즘

1. 12개 워커에서 도로를 하나씩 병렬 실행한다. 각 실행은 새 시드로 빈 도로에서 시작하며, 웜업 없이 시뮬레이션 시간 3,600초 동안 진행한다. 배경차량은 보정된 4,740대/시간의 경로별 유입량과 차량 타입 비율을 따른다.
2. 도로 위 모든 IDM 차량의 스텝 직전 관측과 해당 스텝에서 실행한 가감속·차선 변경을 차량별 임시 버퍼에 모은다. 각 주행에 실행 ID, 차량 ID, 경로 ID, 실제 진입 시각, 종료 사유를 기록한다.
3. 차량이 완주하거나 실패로 주행이 끝나면 유효한 관측–행동 쌍을 저장하고 해당 경로의 주행 수를 1회 올린다. 3,600초에 아직 주행 중인 차량은 버퍼를 폐기하고 주행 수에서도 제외한다. 저장된 주행 수와 유효한 쌍 수는 경로별로 집계한다.
4. 시뮬레이션 실행 ID를 고정 시드로 무작위 배정해 학습용 약 95%, 검증용 약 5%로 분리한다. 같은 실행의 차량은 한 분할에만 배정한다. 두 분할에서 모든 경로의 유효 주행 수가 목표에 도달할 때까지 새 시드로 수집한다.
5. 학습용 실행에서 경로당 19,000회, 검증용 실행에서 경로당 1,000회를 중복 없이 선별한다. 각 분할에서 실제 진입 시각을 기준으로 실행의 초반·중반·후반을 나누고, 각 시간대에서 가능한 한 같은 수를 무작위로 고른다. 한 시간대가 부족하면 같은 분할의 다른 시간대에서 보충하고 경로별 최종 시간대 분포를 기록한다.
6. 선별한 주행의 유효한 관측–행동 쌍을 해당 분할에 모두 사용한다. 학습과 검증을 합쳐 총 48만 회 주행이며, 파일럿 기준 약 9,400만 쌍을 예상한다. 실행의 분할 배정과 경로·시간대별 선별 결과를 저장한다.

## BC 학습

| 항목 | 설정 |
|---|---|
| 초기화 | 새 모델에서 시작 (시드 0) |
| 입력 | 51차원 관측. 링 합류 시 직접 연결된 본선 차선만 탐색하고, 인접 앞차 탐색은 교차로 내부 연결 차선까지 이어간다. 학습 분할의 평균과 표준편차로 정규화 |
| 신경망 | 은닉층 256개 유닛씩 2층, ReLU |
| 출력 | 종방향 가감속 회귀, 차선 변경 3분류 (왼쪽·유지·오른쪽) |
| 손실 함수 | 가감속 평균제곱오차 + 가중 차선 변경 교차 엔트로피. 차선 클래스 가중치는 학습 데이터의 클래스 빈도에 반비례하는 값의 제곱근 사용 |
| 최적화 | Adam, 학습률 0.00042, 배치 크기 8,192, 그래디언트 노름 상한 1.0 |
| 학습 기간 | 100 epoch |
| 학습·검증 분할 | 시뮬레이션 실행 단위로 약 95:5로 분리한 뒤, 경로당 학습 19,000회·검증 1,000회 선별 |
| 평가 체크포인트 | 검증 손실이 가장 낮은 epoch의 모델. 해당 실험에서는 91 epoch |


## BC 평가 (예전 방식)

팀원의 보정 도로와 경로별 배분을 사용해 4,740대/시간 고정 유입으로 평가한다.

1. 도로 하나를 800초 동안 예열한다. 시뮬레이션 802초부터 950초까지 2초마다 도로와 신호 상태를 저장한다.
2. 저장 상태 75개마다 배경차량 투입 시드 1개를 고정하고, 24개 경로를 각각 배정해 총 1,800개 평가 케이스를 만든다. 케이스에는 저장 상태, 시드, 경로, 출발 차선을 기록한다. 시드는 저장 상태를 복원한 뒤의 배경차량 투입을 결정한다.
3. 워커 4개가 케이스를 중복 없이 나눠 처리한다. 워커당 최대 64개 복제 도로를 동시에 실행한다. 각 케이스에서 저장 상태를 복원하고 ego를 고정 중앙 차선에 배치한 뒤 출발 후 첫 30m 동안 차선 변경을 제한한다.
4. 완주, 충돌, 적신호 위반, 잘못된 차선 종료, 또는 시뮬레이션 시간 500초까지 주행한다. 큐에 남은 케이스가 없어도 이미 시작한 주행은 끝까지 처리한다.
5. IDM과 모든 BC 체크포인트에 동일한 1,800개 케이스를 재사용한다. 전체·경로별 완주율과 종료 사유별 건수를 저장하고 `summary.png`를 생성한다. IDM만 `lcSpeedGain=1.0`인 평가 묶음(209번)을 사용한다. 이 묶음의 IDM 기준점은 1,799/1,800회 완주다.

전체 완주율은 24개 경로를 동일한 비중으로 집계한다. 경로별 평가가 75회이므로 작은 차이는 완주율과 함께 성공 건수로 확인한다. 저장 상태 75개는 한 번의 웜업에서 얻은 연속 상태이며, 각 상태의 이후 유입은 시드 하나로 평가한다.

# 개선 사항

## 개선 사항 1: 차선 변경 가중치 완화

데이터셋의 대부분은 차선 유지이기 때문에 그대로 학습을 하면 신경망은 차선 유지만 계속 할 수 있다.
이것을 방지하기 위해 좌우차선 변경에 대해서 제곱근 가중치를 적용했는데 이것이 너무 과할 수 있다는 것이 확인됐다.
그래서 네제곱근, 세제곱근 가중치를 적용해서 학습만 다시 진행한다.

- 결과: 네제곱근 가중치에서 가장 높은 완주율 (95.66%) (세제곱근에서는 95.40%)
- 경로: `results/BC_20261121_210355_4740_lane_root4`

## 개선 사항 2: 황신호 가중치 추가

데이터셋에서 황신호 데이터는 희소하기 때문에 황신호에도 가중치를 적용하면 황신호에서 신호위반 하는 문제를 해결할 수 있을 것이다.

- 결과: 혼합 완주율 95.66% → 95.90%, 적신호 위반 12건 → 48건. 최종 모델에는 적용하지 않았다.
- 경로: `results/BC_20261122_002657_4740_lane_root4_yellow_root4`

## 개선 사항 3: 앞차가 다른 도로 위에 있을 때 차간거리 observation 개선

지금까지 앞차가 다른 도로 위에 올라가있을 때 차간거리를 측정하는 방식에 문제가 있었다. 이를 수정했다.

- 결과: 완주율 96.90%
- 경로: `BC_20261122_132208_calibrated_4740_connected_lane_gaps`

## 개선 사항 4: 좌우 차선의 앞뒤 차간거리 observation 개선

앞차 뒷범퍼 - 내차 앞범퍼로 계산을 할 때 음수는 0m로 clipping을 했다. 이로 인해서 두 차가 거의 나란히 있을 때 차선변경을 시도하면서 충돌이 발생한 것 같다.
좌우 차선의 앞 뒤 차간거리에서 각각 음수, 양수를 허용한다.

- 결과: 출발 제한 없는 혼합 평가 완주율 94.85%, 충돌률 2.29%.

## 개선사항 5: 차선 변경을 하지 못하는 경우

IDM 전문가 수집할 때는 투입 후 30m 동안 차선변경이 허용되지만 BC는 그렇지 않았다. 이로 인해서 차선을 변경하지 못했다.
IDM 전문가도 수집할 때 20m 동안 차선 변경을 허용하지 않게 개선한다.
그리고 최대한 rule based로 하지 않기 위해서 BC에 출발 도로 시작점부터의 위치를 20m 기준으로 정규화한 값 하나를 observation으로 추가한다.

- 결과: 출발 제한 없는 혼합 평가 완주율 96.14%, 충돌률 2.42%.

## 개선 사항 4 + 5

두 개선사항을 따로 적용했을 때는 완주율이 떨어졌지만 동시에 적용할 때 완주율이 증가했다.
최종 체크포인트는 학습 시드 0의 88 epoch 모델이다. 4,740대/시간 혼합 교통에서 출발 제한 없이 동일한 10개 시드로 평가해 완주율 98.10%, 충돌률 0.72%를 기록했다. 같은 데이터로 학습 시드 1에서 다시 학습했을 때는 완주율 97.63%, 충돌률 0.68%였다.

현재 고정 경로 평가, 혼합 평가, GUI 재생은 출발 차선 변경 제한을 기본으로 끈다. 이전 30m 조건은 `--spawn-protect-m 30`으로 재현할 수 있다.

- 경로: `results/BC_20261122_220742_calibrated_4740_signed_gaps_spawn20`

## 추가 혼합 평가: ego 제한 해제

`scripts/evaluate_mixed_traffic.py`에 ego 제한을 끄는 옵션 두 개를 추가했다. 기본값은 기존 혼합 평가와 같다.

- `--no-ego-speed-cap`: ego 속도 명령을 도로 제한속도로 자르지 않는다.
- `--unrestricted-ego`: 속도 상한과 출발 차선 변경 제한을 끄고 교차로 내부 차선 변경을 허용한다. 충돌한 차량도 제거하지 않고(`--collision.action warn`) 실패를 기록한 채 주행을 계속한다.

제한 전체 해제 평가의 `success_rate` 1.0은 실패 후에도 주행을 계속해 모든 차량이 결국 도착했다는 뜻이다. 성능 비교에는 무실패 완주율을 사용한다.


# 무작위 출발 차선

현재 보정 도로에는 24개 경로와 출발 차선을 합쳐 94개 조합이 있다. 최종 BC의 학습 데이터에는 94개가 모두 있었지만, 경로당 19,000회로만 맞췄기 때문에 조합별 주행 수는 3,059~7,296회였다.

`scripts/evaluate_diverse_start_lanes.py`로 독립 시드 25개의 도로 상태 75개를 만들고, 조합당 75회씩 총 7,050회를 평가했다. 4,740대/시간에서 출발 차선 변경 제한 없이 최종 BC의 완주율은 96.47%, 충돌률은 0.57%였다. 같은 상태의 중앙 차선만 집계하면 완주율은 96.89%였다.

가장 취약한 조합은 A4→A3의 오른쪽 0번 차선이었다. 학습에 7,208회(약 301만 스텝)가 포함됐지만 평가에서는 51/75회(68.0%) 완주했다.
