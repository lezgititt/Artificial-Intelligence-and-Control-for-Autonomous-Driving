# 최종 BC Training 알고리즘

전문가 데이터 수집 → 분할 및 선별 → BC 학습 → BC 평가

## 전문가 데이터 수집

- 도로 환경 설정
  - 배경차량 교통량: 윤재님의 traffic calibration 교통량 사용 (총 교통량 4740대/시간)
  - 배경차량 타입 비율: Krauss 35% / IDM 30% / EIDM 20% / ACC 15%
  - 배경차량 속도를 위한 추월 (lcSpeedGain) 설정: IDM만 1.0 (True) -> 속도를 위해 추월하는 것을 학습하기 위해
  - 신호 체계: 단순 신호 체계

- 전문가 데이터 수집
  - 전문가: IDM 단독
  - 목표 데이터: 24개 경로 데이터
  - 목표 수: 경로당 20,000회 (약 1억 쌍 예상)

### 전문가 데이터 수집 알고리즘

1. 12개 워커에서 도로를 하나씩 병렬 실행한다. 각 실행은 새 시드로 빈 도로에서 시작하며, 웜업 없이 시뮬레이션 시간 3,600초 동안 진행한다. 배경차량은 보정된 4,740대/시간의 경로별 유입량과 차량 타입 비율을 따른다.
2. 도로 위 모든 IDM 차량의 스텝 직전 관측과 해당 스텝에서 실행한 가감속·차선 변경을 차량별 임시 버퍼에 모은다. 각 주행에 실행 ID, 차량 ID, 경로 ID, 실제 진입 시각, 종료 사유를 기록한다.
3. 차량이 완주하거나 실패로 주행이 끝나면 유효한 관측–행동 쌍을 저장하고 해당 경로의 주행 수를 1회 올린다. 3,600초에 아직 주행 중인 차량은 버퍼를 폐기하고 주행 수에서도 제외한다. 저장된 주행 수와 유효한 쌍 수는 경로별로 집계한다.
4. 시뮬레이션 실행 ID를 고정 시드로 무작위 배정해 학습용 약 95%, 검증용 약 5%로 분리한다. 같은 실행의 차량은 한 분할에만 배정한다. 두 분할에서 모든 경로의 유효 주행 수가 목표에 도달할 때까지 새 시드로 수집한다.
5. 학습용 실행에서 경로당 19,000회, 검증용 실행에서 경로당 1,000회를 중복 없이 선별한다. 각 분할에서 실제 진입 시각을 기준으로 실행의 초반·중반·후반을 나누고, 각 시간대에서 가능한 한 같은 수를 무작위로 고른다. 한 시간대가 부족하면 같은 분할의 다른 시간대에서 보충하고 경로별 최종 시간대 분포를 기록한다.
6. 선별한 주행의 유효한 관측–행동 쌍을 해당 분할에 모두 사용한다. 학습과 검증을 합쳐 총 48만 회 주행이며, 파일럿 기준 약 9,400만 쌍을 예상한다. 실행의 분할 배정과 경로·시간대별 선별 결과를 저장한다.

## BC 학습

| 항목 | 설정 |
|---|---|
| 초기화 | 새 모델에서 시작 (시드 0) |
| 입력 | 51차원 관측. 링 합류 시 직접 연결된 본선 차선만 탐색하고, 인접 앞차 탐색은 교차로 내부 연결 차선까지 이어간다. 학습 분할의 평균과 표준편차로 정규화 |
| 신경망 | 은닉층 256개 유닛씩 2층, ReLU |
| 출력 | 종방향 가감속 회귀, 차선 변경 3분류 (왼쪽·유지·오른쪽) |
| 손실 함수 | 가감속 평균제곱오차 + 가중 차선 변경 교차 엔트로피. 차선 클래스 가중치는 학습 데이터의 클래스 빈도에 반비례하는 값의 제곱근 사용 |
| 최적화 | Adam, 학습률 0.00042, 배치 크기 8,192, 그래디언트 노름 상한 1.0 |
| 학습 기간 | 100 epoch |
| 학습·검증 분할 | 시뮬레이션 실행 단위로 약 95:5로 분리한 뒤, 경로당 학습 19,000회·검증 1,000회 선별 |
| 평가 체크포인트 | 검증 손실이 가장 낮은 epoch의 모델. 해당 실험에서는 91 epoch |


## BC 평가

팀원의 보정 도로와 경로별 배분을 사용해 4,740대/시간 고정 유입으로 평가한다.

1. 도로 하나를 800초 동안 예열한다. 시뮬레이션 802초부터 950초까지 2초마다 도로와 신호 상태를 저장한다.
2. 저장 상태 75개마다 배경차량 투입 시드 1개를 고정하고, 24개 경로를 각각 배정해 총 1,800개 평가 케이스를 만든다. 케이스에는 저장 상태, 시드, 경로, 출발 차선을 기록한다. 시드는 저장 상태를 복원한 뒤의 배경차량 투입을 결정한다.
3. 워커 4개가 케이스를 중복 없이 나눠 처리한다. 워커당 최대 64개 복제 도로를 동시에 실행한다. 각 케이스에서 저장 상태를 복원하고 ego를 고정 중앙 차선에 배치한 뒤 출발 후 첫 30m 동안 차선 변경을 제한한다.
4. 완주, 충돌, 적신호 위반, 잘못된 차선 종료, 또는 시뮬레이션 시간 500초까지 주행한다. 큐에 남은 케이스가 없어도 이미 시작한 주행은 끝까지 처리한다.
5. IDM과 모든 BC 체크포인트에 동일한 1,800개 케이스를 재사용한다. 전체·경로별 완주율과 종료 사유별 건수를 저장하고 `summary.png`를 생성한다. IDM만 `lcSpeedGain=1.0`인 평가 묶음(209번)을 사용한다. 이 묶음의 IDM 기준점은 1,799/1,800회 완주다.

전체 완주율은 24개 경로를 동일한 비중으로 집계한다. 경로별 평가가 75회이므로 작은 차이는 완주율과 함께 성공 건수로 확인한다. 저장 상태 75개는 한 번의 웜업에서 얻은 연속 상태이며, 각 상태의 이후 유입은 시드 하나로 평가한다.

### 전문가 데이터 수집 알고리즘

1. 12개 워커에서 도로를 하나씩 병렬 실행한다. 각 실행은 새 시드로 빈 도로에서 시작하며, 웜업 없이 시뮬레이션 시간 3,600초 동안 진행한다. 배경차량은 보정된 4,740대/시간의 경로별 유입량과 차량 타입 비율을 따른다.
2. 실제 시뮬레이션에서는 도로 위 모든 IDM 차량을 BC로 제어한다. 매 스텝 직전의 차량·교통·신호 상태를 별도 SUMO에 복원해 IDM의 한 스텝 행동을 얻는다. 원래 관측과 IDM의 가감속·차선 변경을 짝지어 차량별 임시 버퍼에 모은다. 각 주행에 실행 ID, 차량 ID, 경로 ID, 실제 진입 시각, 종료 사유를 기록한다.
3. 차량이 완주하거나 실패로 주행이 끝나면 유효한 관측–행동 쌍을 저장하고 해당 경로의 주행 수를 1회 올린다. 3,600초에 아직 주행 중인 차량은 버퍼를 폐기하고 주행 수에서도 제외한다. 저장된 주행 수와 유효한 쌍 수는 경로별로 집계한다.
4. 시뮬레이션 실행 ID를 고정 시드로 무작위 배정해 학습용 약 95%, 검증용 약 5%로 분리한다. 같은 실행의 차량은 한 분할에만 배정한다. 두 분할에서 모든 경로의 유효 주행 수가 목표에 도달할 때까지 새 시드로 수집한다.
5. 학습용 실행에서 경로당 9,500회, 검증용 실행에서 경로당 500회를 중복 없이 선별한다. 각 분할에서 실제 진입 시각을 기준으로 실행의 초반·중반·후반을 나누고, 각 시간대에서 가능한 한 같은 수를 무작위로 고른다. 한 시간대가 부족하면 같은 분할의 다른 시간대에서 보충하고 경로별 최종 시간대 분포를 기록한다.
6. 선별한 주행의 유효한 관측–행동 쌍을 해당 분할에 모두 사용한다. 24개 경로에서 학습 228,000회와 검증 12,000회를 합쳐 총 240,000회 주행을 선별한다. 약 5,000만 쌍은 잠정 예상치이며, 실제 유효 라벨 수는 수집 후 집계한다. 실행의 분할 배정과 경로·시간대별 선별 결과를 저장한다.

## 단일 라운드 파인튜닝

기준 BC 체크포인트로 주행 데이터를 한 번 수집하고, 같은 체크포인트에서 시작해 한 번 파인튜닝한다. 파인튜닝이 끝나면 기존 고정 평가 목록의 1,800개 케이스에서 기준 BC와 비교한다. 평가에서는 ego 한 대를 BC로 제어하며 배경차량은 각자의 제어기를 사용한다.
